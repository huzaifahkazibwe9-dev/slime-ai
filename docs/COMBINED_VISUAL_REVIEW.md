# Combined visual review evaluation

After preparing a review bundle with `prepare_visual_review.py` and completing both label templates, evaluate them together:

```bash
python evaluate_visual_review_bundle.py \
  data/visual_review_bundle.json \
  data/colour_labels_template.json \
  data/shooter_labels_template.json \
  --board-observation data/board_observation_latest.json \
  --shooter-detection data/shooter_detection.json \
  --pixel-audit data/source_pixel_audit_latest.json \
  --source-screenshot path/to/the/original-screenshot.png
```

The evaluator verifies manifest integrity, exact source-artifact hashes, capture session and timestamp, screenshot dimensions, and the board's source-pixel audit. It reconstructs both original blank templates and checks that the completed files differ only in their intended human annotation fields. Board RGB values and cell coordinates must still match the original board observation; shooter detector records must still match the exact detector JSON.

The evaluator then runs the board-colour and shooter-observation metrics and emits one combined report. It does not combine the two metrics into one accuracy number because they measure different tasks.

Review labels remain user-supplied evidence. Agreement metrics do not independently prove that human labels are correct, that calibration aligns to game tiles, or that shooter colour, ammunition, or slot mapping is correct. Gameplay remains unverified and live taps remain disabled.

The resulting evaluation report also records SHA-256 digests for the exact manifest, completed board-label JSON and completed shooter-label JSON bytes it evaluated. Preserve the report together with those input files when an evaluation needs to be independently reproduced later. These digests identify the reviewed inputs; they do not certify who supplied the human labels or whether those labels are true.

Batch reports can be checked with `verify_batch_report(report)` after loading the saved JSON into a Python object. This verifier checks the report self-digest, the unique capture IDs, screenshot hashes and capture sessions, the per-artifact SHA-256 fields, screenshot identity consistency, strict schema-v1 field sets, capture-session token syntax, timezone-aware ISO-8601 timestamps, and the explicit unverified status of label truth, calibration alignment and gameplay. Schema-v1 reports with changed field sets must be regenerated by the matching evaluator rather than edited by hand.

The report digest is an unkeyed integrity checksum, not a digital signature or proof of authorship. The verifier also checks that pooled confusion matrices, sample support, accuracy, per-class board metrics, shooter ammunition counts, ammunition MAE is non-negative, is zero when every detected reading matches, and is no lower than the minimum implied by integer mismatches; coverage totals are arithmetically consistent within the saved report. It also rejects noncanonical board/shooter colour labels, unsupported visibility labels, malformed slot-coordinate labels, and boolean values masquerading as numeric per-class metrics. Shooter coverage buckets must use the known visibility, sample-quality and ammunition-OCR status vocabularies, and every bucket count must be positive. Confirmed visibility coverage counts must also match the positive actual-label row totals in the visibility confusion matrix; predicted-only rows with zero actual samples are excluded. Position labels must be canonical one-based coordinates inside the detector's calibrated 3×4 panel. This detects internally inconsistent edits, but it cannot prove that a consistently re-authored report reflects the original source artifacts; preserve those artifacts and rerun the evaluator for independent reproduction. A person who can edit a report can also recompute its digest. For independent audit, preserve the original batch manifest and source artifacts, then rerun the evaluator and compare the resulting report and digest.
